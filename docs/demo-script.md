# Demo Script

Короткий сценарий защиты на 5 минут. Без лишних действий и без риска сломать прогретый индекс.

## Перед выходом

- Убедиться, что сервер уже запущен
- Не запускать полный импорт на сцене
- Открыть приложение на вкладке `Поиск`
- Держать рядом вкладку `Данные`, `Динамика` и `Метрики`

## Порядок показа

### 1. Коротко показать масштаб данных

Открыть вкладку `Данные`.

Что показать:

- количество товаров
- количество контрактов
- количество профилей
- последний успешный import job

Что сказать:

- система уже работает на полном датасете
- при подготовке строится индекс товаров, словарь для typo correction и профили заказчиков

### 2. Показать умный поиск с исправлением раскладки

Перейти на вкладку `Поиск`.

Ввести или оставить запрос:

- `aktirf smartbuy 16`

Что показать:

- `Исправленный запрос`
- `Что использовалось в поиске`
- `Исправления раскладки`
- `Синонимы`

Что сказать:

- пользователь может ошибиться раскладкой клавиатуры
- система сначала нормализует запрос, исправляет раскладку, применяет синонимы и только потом ищет

### 3. Показать персонализацию по заказчику

На той же вкладке оставить выбранным `Demo profile 1`.

Запрос:

- `иммунодепрессанты`

Что показать:

- блок `Профиль заказчика`
- explanation у первого результата
- score factors `history_product`, `history_category` или `history_tokens`

Что сказать:

- один и тот же запрос для разных заказчиков может иметь разную выдачу
- причина в том, что профиль строится по реальной истории контрактов

### 4. Показать динамическую перестройку выдачи

На одном из запросов нажать:

- `Не релевантно`

Потом перейти на вкладку `Динамика`.

Что показать:

- позиции до и после
- что результат сместился сразу

Что сказать:

- после действия пользователя мы не перестраиваем весь глобальный индекс
- мы обновляем live-сигналы сессии и используем их уже в следующем поиске

### 5. Показать метрики

Перейти на вкладку `Метрики`.

Что показать:

- `baseline`
- `personalized`
- прирост по `NDCG@10`, `MRR@10`, `Recall@20`, `Success@5`

Что сказать:

- персонализация улучшает качество не только визуально, но и по численным метрикам

## Самый безопасный набор запросов

- `aktirf smartbuy 16`
- `иммунодепрессанты`
- `конфеты`
- `молоко`

## Очень короткая речь

Если нужно объяснить систему за 30 секунд:

- мы строим индекс товаров и профиль заказчика по контрактной истории
- при поиске нормализуем запрос, исправляем ошибки и ищем кандидатов через FTS5
- затем персонализируем ранжирование по истории закупок и live-сигналам текущей сессии
- поэтому пользователь видит не просто поиск по словам, а персонализированную и объяснимую выдачу

## Чего не делать на сцене

- не очищать базу
- не запускать полный импорт большого датасета
- не показывать слишком много разных запросов
- не уходить в детали реализации раньше времени

## Что отвечать на вопрос “почему выдача изменилась?”

- сначала сработал базовый поиск по каталогу
- затем сработали профильные сигналы заказчика
- после действий пользователя добавились session-сигналы
- именно они изменили порядок результатов
